本页是辅助中文译文，以[英文原文](../en/team.md)为准。

<a id="overview-and-evidence-index"></a>

## 总览与证据索引

当前工作流区分需求、实施和独立验收。

[E1 流程](process.md)说明顺序；[E2 任务活动](tracker.md#current-role-activity)记录当前语言迁移活动，并保留之前的文档工作历史。

| 角色 | 职责 | 交付 |
| --- | --- | --- |
| PM / 协调代理 | 明确范围、维护公开任务、制定验收标准、保护用户正在使用的工作区，并发布已授权且通过审核的工作。 | 包含基线、范围和验收标准的任务。 |
| Engineer 代理 | 阅读任务与源码、修改批准文件、执行适当检查并报告限制。 | 改动文件、准确检查结果和任务内 JSON 报告。 |
| 独立 QA 代理 | 审核 Engineer 最终差异并验证验收标准，不自行批准自己的工作，不悄悄修改产品。 | 逐项通过/失败、证据及所需修复。 |
| 运维 / on-call（计划） | 定义部署回滚流程、用户影响告警处理和受限修复；本批次中该角色尚未运行值班响应流程。 | 后续部署/回滚证据，以及告警 → 诊断 → 授权修复 → 业务恢复验收。 |
| 人类负责人 | 确定产品优先级、授权当前范围之外的操作，并给出最终体验反馈。 | 通过 PM 传达决定与反馈。 |

<a id="working-agreements"></a>

## 工作约定

PM 负责与用户沟通，代理向 PM 报告并复用同一任务目录。

代理只能写入 PM 明确批准的文件；只读调查不意味着可以修改其他位置。

即使公开任务评论由同一个协调账号发布，Engineer 与 QA 仍必须是独立执行角色。

任务内 JSON 交付和原始日志默认保持私有；公开任务跟踪只接收简洁、真实并链接整理后证据的摘要。

人工生产发布和回滚决定由已授权的发布负责人作出；未来响应代理必须使用限定修复权限，达到权限边界时交回人工处理。
